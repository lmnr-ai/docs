---
title: LLM Cost and Token Tracking
---

Laminar is an open-source, OpenTelemetry-native observability platform for AI agents. It records token usage and dollar cost on every LLM span, then aggregates those numbers across the whole trace, so you can see what an agent run cost, which model, user, or customer drove the spend, and where the tokens went.

For [auto-instrumented providers and frameworks](/tracing/integrations/overview) this works with no configuration. Initialize the SDK and every LLM call carries token counts and cost. The rest of this page covers what you can break that spend down by, how the numbers are calculated, and how to instrument calls Laminar does not trace automatically.

## What you can track

Every LLM span carries input tokens, output tokens, and the cost of that call. Laminar rolls them up so you can attribute spend by:

- **Model and provider**, including a mix of providers in one run
- **Agent or workflow**, through span and trace names
- **Session**, a full conversation or multi-step run
- **User**, through the user ID on the trace
- **Metadata and tags**, so you can slice by environment, customer, feature, or experiment
- **Individual run**, since every trace carries its own total

Costs appear on the trace and on each span in the UI, and are queryable across traces from the [SQL editor](/platform/sql-editor).

## Which models and providers are covered

Laminar calculates cost for effectively every model from every major provider, and pricing is kept current as providers change it. Models released after the SDK version you have installed still price correctly, so there is nothing to upgrade when a provider ships something new.

Two cases need a price from you:

- A **private, self-hosted, or fine-tuned model** that has no public list price.
- A **rate that differs from list price**, such as negotiated or committed-use pricing.

Both are handled by defining a per-project rate under **Settings > Model costs**. See [Custom model costs](/platform/custom-model-costs).

## How Laminar calculates cost

Cost is computed at ingestion from three things on the span:

1. Provider name (`gen_ai.system`)
2. Request model name (`gen_ai.request.model`)
3. Token counts

All three are required. If any is missing, cost stays at zero, which is the most common reason a span shows no price. See the [span attribute reference](/tracing/structure/span-attribute-reference) for the full key list.

Where a provider reports cached or reasoning tokens, Laminar counts them and prices them at their own rates rather than folding them in with ordinary input and output. This matters on reasoning models, where output tokens alone understate the bill, and on long-context agents, where treating cached reads as full-price input overstates it.

Prices apply at ingestion, so changing a rate does not re-cost spans you have already recorded.

## Attributing cost across your system

A per-call cost is only useful if you can group it. Laminar's trace primitives are what turn a pile of LLM spans into a cost breakdown, and they work the same whether the spans were auto-instrumented or created by hand.

<Tabs items={['TypeScript', 'Python']}>
  <Tab title="TypeScript">
    ```typescript
    import { Laminar, observe } from '@lmnr-ai/lmnr';

    await observe({ name: 'support-agent' }, async () => {
      Laminar.setTraceSessionId(conversationId);
      Laminar.setTraceUserId(userId);
      Laminar.setTraceMetadata({
        environment: 'production',
        customer: 'acme',
        feature: 'inbox-triage',
      });

      // every LLM call inside this trace now carries those dimensions
      await runAgent();
    });
    ```
  </Tab>

        Laminar.set_trace_session_id(conversation_id)

Metadata is the one to reach for when you need per-customer or per-feature cost reporting. It is queryable in the SQL editor, so "what did this customer cost us last month" is one query rather than an export.

## Instrumenting calls Laminar does not trace automatically

Auto-instrumentation covers the providers and frameworks on the [integrations list](/tracing/integrations/overview). You need to create LLM spans by hand for:

- Self-hosted or fine-tuned models behind your own endpoint
- Providers Laminar does not instrument yet
- Direct HTTP calls to an LLM API
- Custom inference servers

### Provider names for manual spans

When you create an LLM span yourself, set the provider name to one of the values below so Laminar can match pricing. This table is the list of identifier strings, not the list of models Laminar can price: auto-instrumented calls set this for you, and any model can be priced through custom model costs.

| Provider | Provider name | Example model |
|---------|----------------|---------------|
| OpenAI | `openai` | `gpt-5-mini`, `gpt-5-mini-2025-08-07` |
| Anthropic | `anthropic` | `claude-sonnet-4-5` |
| Google Gemini | `gemini`, `google-genai` | `models/gemini-3-pro-preview` |
| Azure OpenAI | `azure-openai` | `gpt-5-mini` |
| AWS Bedrock (Anthropic) | `bedrock-anthropic` | `claude-3-5-sonnet-20241022-v2:0` |
| Mistral | `mistral` | `mistral-large-2407` |
| Groq | `groq` | `llama-3.1-70b-versatile` |

If your provider is not listed, record token usage and set explicit cost attributes, or define the price once under Settings > Model costs.

### Required attributes

| Attribute | Description |
|-----------|-------------|
| Provider | Provider name, for example `openai`, `anthropic`, `custom` |
| Request model | Model name you requested |
| Response model | Model name returned by the API |
| Input token count | Number of input tokens |
| Output token count | Number of output tokens |

Set `spanType: 'LLM'` when creating the span. Without it the span renders as a generic operation and is excluded from transcript view.

Use the exact model string the provider API returns. Simplifying `gpt-5-mini-2025-08-07` to `gpt-5-mini` changes which price is matched.

### Example

<Tabs items={['TypeScript', 'Python']}>
  <Tab title="TypeScript">
    ```typescript
    import { Laminar, LaminarAttributes } from '@lmnr-ai/lmnr';

    const span = Laminar.startSpan({ name: 'custom_llm_call', spanType: 'LLM' });

    try {
      const response = await fetch('https://api.custom-llm.com/v1/completions', {
        method: 'POST',
        body: JSON.stringify({
          model: 'custom-model-1',
          messages: [{ role: 'user', content: 'What is the longest river in the world?' }],
        }),
      }).then((res) => res.json());

      span.setAttributes({
        [LaminarAttributes.PROVIDER]: 'custom-provider',
        [LaminarAttributes.REQUEST_MODEL]: 'custom-model-1',
        [LaminarAttributes.RESPONSE_MODEL]: response.model,
        [LaminarAttributes.INPUT_TOKEN_COUNT]: response.usage?.input_tokens ?? 0,
        [LaminarAttributes.OUTPUT_TOKEN_COUNT]: response.usage?.output_tokens ?? 0,
        // Optional: explicit costs (override calculated pricing)
        [LaminarAttributes.INPUT_COST]: 0.001,
        [LaminarAttributes.OUTPUT_COST]: 0.002,
        [LaminarAttributes.TOTAL_COST]: 0.003,
      });

      return response;
    } catch (error) {
      span.recordException(error as Error);
      throw error;
    } finally {
      span.end();
    }
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import requests
    from lmnr import Attributes, Laminar

    span = Laminar.start_span(name="custom_llm_call", span_type="LLM")
    try:
        response = requests.post(
            "https://api.custom-llm.com/v1/completions",
            json={
                "model": "custom-model-1",
                "messages": [
                    {"role": "user", "content": "What is the longest river in the world?"}
                ],
            },
        ).json()

        span.set_attributes({
            Attributes.PROVIDER.value: "custom-provider",
            Attributes.REQUEST_MODEL.value: "custom-model-1",
            Attributes.RESPONSE_MODEL.value: response.get("model"),
            Attributes.INPUT_TOKEN_COUNT.value: response.get("usage", {}).get("input_tokens", 0),
            Attributes.OUTPUT_TOKEN_COUNT.value: response.get("usage", {}).get("output_tokens", 0),
            # Optional: explicit costs (override calculated pricing)
            Attributes.INPUT_COST.value: 0.001,
            Attributes.OUTPUT_COST.value: 0.002,
            Attributes.TOTAL_COST.value: 0.003,
        })
    finally:
        span.end()
    ```

</Tabs>

## Setting your own prices

If Laminar cannot look up a price for your provider and model, you have two options:

- **Define a price once in the UI.** Add a per-project rate under **Settings > Model costs** and Laminar prices every matching span from it, so you do not set cost attributes on every call. See [Custom model costs](/platform/custom-model-costs).
- **Attach explicit cost attributes** per span, as in the examples above. These take precedence over every price table, including your own custom prices.

## Viewing costs

Costs show up:

- On **trace details**, as the sum of every LLM call in the run. See [Viewing traces](/platform/viewing-traces).
- On **individual LLM spans**, as the cost of that call.
- On **dashboards**, aggregated by provider, model, or any dimension you set. See [Dashboards](/custom-dashboards/overview).
- In the **[SQL editor](/platform/sql-editor)**, for reporting across traces.

## Finding wasted spend

Cost tracking tells you what you spent. To find what you wasted, use [Signals](/signals/introduction): plain-language instructions that read whole agent runs and flag the patterns that quietly drive cost, like a tool call retried until the agent gives up. Because a Signal sees the full run rather than isolated token counts, it catches waste that a per-call number cannot show.

## FAQ

**Why is cost showing as zero on my spans?**
Cost needs the provider name, the request model, and token counts. Missing any one of the three leaves cost at zero. A model string that does not match the provider's exact naming has the same effect.

**Can I see cost per user, per session, or per customer?**
Yes. Set a [user ID](/tracing/structure/user-id), [session ID](/tracing/structure/sessions), or [metadata](/tracing/structure/metadata) on the trace and cost aggregates by any of them.

**Which models and providers are supported?**
Effectively every model from every major provider, with pricing kept current. Private, self-hosted, and fine-tuned models are priced through [custom model costs](/platform/custom-model-costs).

**Are cached and reasoning tokens counted?**
Yes, where the provider reports them. Both are priced at their own rates rather than as ordinary input and output.

**Can I override the calculated cost?**
Yes. Explicit cost attributes on a span take precedence over every price table.

**Can Laminar cap or block my spending?**
No, and no observability platform can. Enforcing a hard limit means refusing a request while it is in flight, which requires sitting in the request path. Laminar records what happened and can flag expensive runs through Signals, but it does not gate calls.

## Troubleshooting

| Symptom | Cause |
|---------|-------|
| Cost is zero | Provider name or request model missing, or the model string does not match the provider's naming |
| Cost looks too high on a long-context agent | The provider is not reporting cached tokens, so cached reads are priced as full input |
| A custom price is not applying | Custom-cost matching is exact on both model and provider. See [Custom model costs](/platform/custom-model-costs) |
| Span shows tokens but renders as a generic operation | `spanType` was not set to `LLM` |
