## Available Tools

### Query

- `query_laminar_sql`  
  Run read-only ClickHouse SQL across Laminar data and get JSON back. Use this to find trace IDs, filter by time/session/status, or pull raw span fields (`input`, `output`, `attributes`).
- `list_projects`  
  List the Laminar projects you can access, with their workspaces. When you sign in with OAuth, the agent calls this first and passes a project's `id` as `projectId` to every other tool.

### Signals

- `list_signals`  
  List the project's [signals](/signals/introduction) with their prompt, payload schema, trigger, filters and mode. Signal events are queryable with `query_laminar_sql` (`signal_events`).
- `get_signal`  
  Get one signal with its trigger, filters and mode.
- `list_signal_versions`  
  List a signal's definition (prompt and payload schema) versions, oldest first.
- `create_signal`  
  Create a signal: an LLM judge that runs a prompt on matching traces and extracts a structured payload. Like the UI, it also creates a critical-severity alert subscribed to your email.
- `update_signal`  
  Update a signal. Only the fields you pass change. Changing the prompt or payload schema adds a definition version.
- `delete_signal`  
  Delete a signal with its triggers, alerts and events. This is irreversible.

<Note>
  `create_signal`, `update_signal` and `delete_signal` need OAuth sign-in. With a project API key,
  they return an error.
</Note>

### LLM profiles

- `list_llm_profiles`  
  List the workspace's LLM profiles: the provider credentials and models that signals and the playground run on. Secrets come back masked.
- `get_llm_profile`  
  Get one LLM profile. Secrets come back masked.
- `create_llm_profile`  
  Create a workspace LLM profile. Secrets you pass are stored encrypted and never returned.
- `update_llm_profile`  
  Update an LLM profile. Only the fields you pass change; `models` replaces the whole list.
- `delete_llm_profile`  
  Delete an LLM profile. Refused while a signal or feature route uses it.

### Traces

- `add_trace_tags`  
  Add tags to a trace, for example to mark traces you reviewed. Tags the trace already has are kept. Tags are queryable with `query_laminar_sql` (`traces.tags`).
- `get_trace_context`  
  Get an LLM-optimized summary of a single trace: span tree, timings, LLM inputs/outputs, and errors. Use this to quickly understand what happened in a specific run once you have a trace ID.

### Agent

- `ask_agent`  
  Ask [Laminar Agent](/platform/laminar-agent) a question in plain language and get a grounded answer back. The agent runs read-only SQL and reads trace context for you, so you do not have to write the queries yourself. Pass a `prompt`; the response returns a `conversationId` you can pass back on the next call to continue the conversation.

<Note>
  `get_trace_context` and `ask_agent` are available on Laminar Cloud. Self-hosted open-source builds
  don't list them.
</Note>

<Note>
  Every tool acts on one project. With a project API key, that is the key's project. With OAuth, it
  is the `projectId` the agent passes, and Laminar checks that you are a member of that project on
  every call. The SQL tool is read-only (`SELECT` only). If trace context truncates long inputs or
  outputs, use SQL to fetch full fields.
</Note>

<Tip>
  Use `ask_agent` when you want a quick answer without writing SQL; use `query_laminar_sql` and
  `get_trace_context` when your assistant should pull raw rows or trace structure to reason over
  itself.
</Tip>

## Connect Your Client

The server URL is `https://api.lmnr.ai/v1/mcp`. It speaks Streamable HTTP, so there is nothing to install. There are two ways to authenticate:

- **Sign in with OAuth.** Add the server with no header. Your client opens a browser, you sign in to Laminar and approve access, and the tools run as you, across every project you belong to.
- **Project API key.** Create a key in the Laminar dashboard and send it as `Authorization: Bearer <key>`. The tools are bound to that key's project.

<Tabs items={['Claude Code', 'Codex', 'Claude', 'ChatGPT', 'Cursor', 'Other']}>
  <Tab title="Claude Code">
    **Sign in with OAuth**

    ```bash
    claude mcp add --transport http laminar https://api.lmnr.ai/v1/mcp
    claude mcp login laminar
    ```

    `claude mcp login` opens the browser. You can also run `/mcp` inside a Claude Code session to sign in. Claude Code refreshes the token on its own, so you only sign in once. Add `--scope user` to `claude mcp add` to use the server in every project.

    **Project API key**

    ```bash
    claude mcp add --transport http laminar https://api.lmnr.ai/v1/mcp \
      --header "Authorization: Bearer <YOUR_PROJECT_API_KEY>"
    ```

  </Tab>
  <Tab title="Codex">
    The Codex CLI and IDE extension share `~/.codex/config.toml`, so you set the server up once.

    **Sign in with OAuth**

    Add the server with no token:

    ```toml
    [mcp_servers.laminar]
    url = "https://api.lmnr.ai/v1/mcp"
    ```

    Then sign in:

    ```bash
    codex mcp login laminar
    ```

    The command opens the browser. On a machine without one, add `--no-browser`, open the printed URL yourself, and paste the redirect URL back into the terminal.

    **Project API key**

    Put the key in an environment variable that is set wherever Codex runs, and point Codex at the variable:

    ```toml
    [mcp_servers.laminar]
    url = "https://api.lmnr.ai/v1/mcp"
    bearer_token_env_var = "LMNR_PROJECT_API_KEY"
    ```

    Codex stores only the variable name. To store the key itself instead, set the header directly:

    ```toml
    [mcp_servers.laminar]
    url = "https://api.lmnr.ai/v1/mcp"
    http_headers = { "Authorization" = "Bearer <YOUR_PROJECT_API_KEY>" }
    ```

  </Tab>
  <Tab title="Claude">
    Add Laminar as a custom connector on claude.ai. It then works in Claude Desktop and the mobile apps too.

    **Sign in with OAuth**

    On a Free, Pro, Max or Ultra plan:

    1. Open **Customize > Connectors**, select **Add**, then **Add custom connector**.
    2. Name it `Laminar`, enter `https://api.lmnr.ai/v1/mcp`, and click **Continue**.
    3. Under **Authentication**, choose **Sign in now** or **Sign in when needed**.
    4. Under **OAuth client**, choose **Register automatically**. Laminar doesn't support **Use Claude's published identity**.
    5. Click **Add**, then **Connect**, and sign in to Laminar in the browser.

    On a Team or Enterprise plan, an Owner adds the connector once under **Organization settings > Connectors** (**Add**, then **Custom**, then **Web**) with the same settings. Each member then opens **Customize > Connectors**, finds Laminar, and clicks **Connect** to sign in with their own account.

    To use it in a chat, click **+** in the message box, select **Connectors**, and turn on Laminar.

    **Project API key**

    Choose **No sign-in** under **Authentication**. Then, under **Request headers**, add an `authorization` header with the value `Bearer <YOUR_PROJECT_API_KEY>`. Include the `Bearer ` prefix: Claude sends the value exactly as you type it.

    <Note>
      Request headers are in beta and only some organizations have them. If you don't see **Request
      headers** in the dialog, use OAuth.
    </Note>

  </Tab>
  <Tab title="ChatGPT">
    Custom MCP servers are added on ChatGPT on the web. Your plan and workspace settings must allow them; on a workspace plan, an admin may need to turn them on first.

    **Sign in with OAuth**

    1. Open [ChatGPT Plugins](https://chatgpt.com/plugins), click **+**, then **Add custom MCP server**.
    2. Name it `Laminar` and add a short description.
    3. Under **Connection**, enter `https://api.lmnr.ai/v1/mcp`.
    4. Choose **OAuth** for authentication, read the warning, and select **I understand and want to continue**.
    5. Select **Create as a plugin**, then sign in to Laminar in the browser.

    To use it in a chat, type `@` in the message box and select Laminar. When Laminar adds tools, open the server in ChatGPT Plugins and select **Refresh**.

    **Project API key**

    ChatGPT doesn't let you set a custom `Authorization` header for an MCP server, so use OAuth.

  </Tab>
  <Tab title="Cursor">
    Add the server to `~/.cursor/mcp.json` to use it in every project, or to `.cursor/mcp.json` for one project.

    **Sign in with OAuth**

    ```json
    {
      "mcpServers": {
        "laminar": {
          "url": "https://api.lmnr.ai/v1/mcp"
        }
      }
    }
    ```

    With no headers, Cursor finds Laminar's sign-in page, registers itself, and asks you to sign in to Laminar in the browser. It renews the token on its own.

    **Project API key**

    ```json
    {
      "mcpServers": {
        "laminar": {
          "url": "https://api.lmnr.ai/v1/mcp",
          "headers": {
            "Authorization": "Bearer <YOUR_PROJECT_API_KEY>"
          }
        }
      }
    }
    ```

  </Tab>
  <Tab title="Other">
    Check your client's documentation for where its MCP settings live, then use:

    - **Transport:** Streamable HTTP
    - **URL:** `https://api.lmnr.ai/v1/mcp`
    - **Auth:** OAuth 2.1, or a project API key

    **Sign in with OAuth**

    Leave out the `Authorization` header. Clients that support MCP OAuth (dynamic client registration with PKCE) discover Laminar's authorization server from the server's `401` response and prompt you to sign in. Laminar doesn't issue fixed client IDs, so a client that needs one can't sign in. Use a project API key instead.

    **Project API key**

    Send `Authorization: Bearer <YOUR_PROJECT_API_KEY>` on every request.

  </Tab>
</Tabs>

For self-hosted deployments, replace the base URL with your instance (for example, `https://laminar.example.com/v1/mcp`). To run against a local app-server, use `http://localhost:8000/v1/mcp`. Claude and ChatGPT connect from their own cloud, so they need a public HTTPS URL. To enable OAuth sign-in on a self-hosted instance, set `MCP_RESOURCE_URL` to that same URL on **both** the frontend and the app-server. Without it, the MCP server accepts project API keys only.

## Example Questions You Can Ask Your LLM

- “What failed in the most recent run for my `dev-claude` session?”
- “Find the latest error trace and summarize the root cause.”
- “Which tool call failed first in the last 20 minutes?”
- “Show me the spans where the model returned an empty response today.”
- “List the 5 slowest traces from the last hour and summarize the slowest one.”
- “Find traces where `status = 'error'` and the top span name contains `checkout`.”
- “Compare the token usage between the last two successful runs.”
- “Which failure clusters cost the most this week, and open the most expensive trace in the biggest one.”
