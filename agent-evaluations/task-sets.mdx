sidebarTitle: Task sets

A task set is a named, versioned group of [agent evaluation](/agent-evaluations/introduction) cases that Laminar stores for you. You define the cases once, then run the same version against every new version of your agent, so a score change means the agent changed rather than the test. Anyone on the project can add cases with `lmnr-cli eval push`, and every run records exactly which version of the cases it used.

## Where task sets live

Each agent in your [evals folder](/agent-evaluations/evals-folder) has two parts, and they are kept in different places:

| | Agent scripts | Task sets |
| --- | --- | --- |
| What | `agent.yaml`, the Harbor agent class, Dockerfiles, start and seed scripts | The cases: `task.toml`, `instruction.md`, per-case data, verifier |
| Changes when | Your code changes | Someone adds or edits a case |
| Source of truth | Your repo | Laminar |

Laminar stores each pushed version of both, plus a snapshot of whatever each run used.

Agent scripts depend on your code: a new database schema or a different start command changes them. Keeping them in the repo means they change in the same commit as the code, and your coding agent can update them alongside it. Task sets are data, so Laminar stores them, and anyone with access to the project can add cases without write access to your repo.

If your repo has no `evals/<agent>/` directory, `lmnr-cli eval run` uses the latest copy of the agent scripts stored in Laminar instead.

## Publish a task set

`lmnr-cli eval push` uploads your local copy and makes it the latest version:

```bash
lmnr-cli eval push support            # the agent's scripts and every local task set
lmnr-cli eval push support/billing    # one task set
```

Each push gets the next version number. `push` also writes `.lmnr.json` into the task set directory, which records the version your copy is now based on.

If someone else pushed the task set since your copy's version, `push` merges their version in first, task by task: tasks only they changed are taken, tasks only you changed are kept, and then your push goes through. A task that both of you changed stops the push with exit code `22` (`merge_conflict`) and changes nothing. Move your copy of that task aside, pull, and re-apply your edit.

## Fetch a task set

`lmnr-cli eval pull` brings Laminar's latest version into your evals folder:

```bash
lmnr-cli eval pull support/billing       # one task set
lmnr-cli eval pull support/billing@3     # a specific version
lmnr-cli eval pull support --all         # every task set of the agent
```

The pull merges with your local copy the same way a push does, so local edits you haven't pushed yet are kept. `--all` also fetches the agent scripts, but only when `evals/<agent>/` has no `agent.yaml`: if your repo has the scripts, its copy wins. You don't need a local copy to run a task set: `lmnr-cli eval run` downloads any task set the evals folder doesn't have.

To fetch only the agent scripts, for example ones the [Laminar agent](/platform/laminar-agent) wrote and stored in Laminar, pull the agent and commit the result to your repo:

```bash
lmnr-cli eval pull support
```

If a script you have locally differs from Laminar's copy, the pull stops with exit code `22` (`merge_conflict`) and lists the files, without writing anything. Commit or move your changes aside first, or pass `--force` to overwrite them.

To see what Laminar has, run `lmnr-cli eval list`:

```
Agent    Task set   Head
support  (scripts)  v4
support  billing    v7
support  refunds    v2
```

## Every run records the versions it used

When you run evals, `lmnr-cli` records exactly which task set version and which agent scripts the run used, and links the run's [evaluation](/evaluations/concepts) to them. If your local copy has changes you haven't pushed, the run stores them as a snapshot: it is kept with the run, but it doesn't become the latest version. Only `push` changes the latest version, so a CI job on a pull request branch or a local experiment can't replace the cases everyone else runs.

This makes runs repeatable. To compare a new version of your agent against an older run, run the same task set version:

```bash
lmnr-cli eval run support --task-set billing@7
```

Each run of a task set is charted in the evaluation group `<agent>/<task set>`, for example `support/billing`, so [comparing runs](/evaluations/comparing-runs) shows how your agent's score changed over time on the same cases.

## The Task sets page

The **Task sets** page in your Laminar project lists each agent's task sets with their latest version. Open a task set to browse its tasks and their files, see each version and which tasks it added, removed, or changed, and find the evaluations that ran it. The **Agent scripts** tab shows the scripts each version of the agent ran with, next to the git commit of your repo at the time. An evaluation run from a task set links back to the task set and the version it ran.
