## FAQ

Fixes for the most common problems when running [agent evaluations](/agent-evaluations/introduction) with `lmnr-cli eval run`.

<AccordionGroup>
  <Accordion title="A change to the app or the image doesn't show up">
    `lmnr-cli` rebuilds the `lmnr.yaml` images on every run, but Docker's layer cache can still hide a change, for example a `RUN` step that downloads "latest". Check the file inside a running container, then clear the cache with `docker builder prune` or bump a cache-busting `ARG` placed before the stale step.
  </Accordion>
  <Accordion title="The app can't see an env var from harbor.yaml">
    `agents[].env` reaches every command the agent runs. If the start script launches the app with `env -i`, it must forward each name explicitly.
  </Accordion>
  <Accordion title="The trial trace has no LLM or tool calls">
    Either the app isn't instrumented with Laminar, or it didn't receive `LMNR_TRAJECTORY_PATH`. See [Capture the trajectory](/agent-evaluations/trajectories).
  </Accordion>
  <Accordion title="Job output shows [REDACTED] in odd places">
    A secret's value is very short, so every occurrence of it in the output is redacted. Use long, distinctive placeholder values.
  </Accordion>
  <Accordion title="Where are the logs for a failed trial?">
    For local runs, in `evals/<suite>/jobs/<timestamp>/`. For `--remote` runs, Harbor's job output stays in the sandbox: open the trial's trace in Laminar instead.

    Each local trial has `agent/` (your logs and `result.json`), `verifier/` (`reward.txt`, `test-stdout.txt`), and `exception.txt` with the agent's traceback if it raised.
  </Accordion>
</AccordionGroup>
