title: Run Agent Evaluations with lmnr-cli eval run
sidebarTitle: Run evals with lmnr-cli
---

`lmnr-cli eval run` runs every [agent evaluation](/agent-evaluations/introduction) dataset in your `evals/` folder, locally on Docker or in Laminar's cloud sandboxes with `--remote`, and records each trial in Laminar with its trace.

Run it from the repo root, since that is where it looks for `.env` and `.env.local`. Use **local** mode while you iterate, after every change. Use **`--remote`** to run many more trials at once: `lmnr-cli` uploads the images and the evals folder, starts the run in Laminar, and prints the run's log until it ends. Ctrl-C stops following the log, and the run goes on in Laminar. Results appear in the project as trials finish.

| | Local | `--remote` |
| --- | --- | --- |
| Harbor runs | On your machine | In a Laminar sandbox |
| Trials run | On your Docker | In Laminar sandboxes, one per trial |
| You need | Docker, uv, `LMNR_PROJECT_API_KEY` | Docker, `lmnr-cli login` (or `LMNR_PROJECT_API_KEY` in CI) |
| Harbor's job output | `evals/<dataset>/jobs/` | The trial's **Files** tab in Laminar |

<Note>
Both modes need Docker on the machine where you run `lmnr-cli`, because that is where the images are built. In remote mode the built images are then uploaded.
</Note>

```bash
lmnr-cli eval run                                    # every dataset in ./evals
lmnr-cli eval run --dataset support --task "duplicate-*" --n-attempts 3
lmnr-cli eval run --task duplicate-charge            # one case
lmnr-cli eval run --remote --n-concurrent 20
lmnr-cli eval run --remote --model anthropic/claude-sonnet-5
```

| Flag | What it does |
| --- | --- |
| `[dir]` | The evals folder. Defaults to `evals`. |
| `--dataset <name>` | Run only this dataset folder. Repeatable. |
| `--task <glob>` | Run only tasks whose folder name matches the glob. Repeatable. |
| `--n-attempts <n>` | Trials per task. Overrides `harbor.yaml`. |
| `--n-concurrent <n>` | Concurrent trials. Overrides `harbor.yaml`. |
| `--model <name>` | Agent model. Overrides `harbor.yaml`. |
| `--env KEY[=VALUE]` | Extra agent env var. Repeatable. A bare `KEY` is read from your environment. |
| `--json` | Print a JSON summary instead of logs. |

## Which tasks and group a run uses

Before it runs a dataset, `eval run` compares its `tasks/` folder with the dataset's `lmnr.lock` and picks the [evaluation group](/evaluations/comparing-runs#group-runs-to-compare-them) the results go to:

- **`tasks/` matches the version `lmnr.lock` pins**: the run reports to `<dataset> v<N>`.
- **`tasks/` is missing, empty, or holds an older version you haven't edited**: `eval run` first pulls the pinned version, as `lmnr-cli eval pull` would, then reports to `<dataset> v<N>`. This is what happens on a fresh clone and in CI.
- **You edited tasks since the last pull or push**: the run uses your local tasks, prints a warning, and reports to `<dataset> unversioned`.
- **No `lmnr.lock`**, because the dataset was never pushed: the run uses the local tasks and reports to `<dataset> unversioned`.

`--task` filters which tasks run without changing the group. [Eval datasets](/agent-evaluations/eval-datasets) covers pushing and pulling versions.

## Read a remote trial's files

In an evaluation from a `--remote` run, each trial has a **Files** tab next to its trace. It shows the dataset folder as it was uploaded, with only this trial's task in `tasks/`, plus a `trial output/` folder with Harbor's output for the trial: the agent's logs and `result.json`, and the verifier's reward and output. The trial output is uploaded when the dataset's run ends.

## In CI

Use `--json` and the exit code. A local run prints `{mode: "local", datasets, failed, url}`. A `--remote` run follows the run to the end, then prints `{mode: "remote", uploadId, sandboxId, datasets, url, evaluations, exitCode}`. `datasets` lists each dataset folder with the evaluation group it reported to, and `evaluations` holds a link to each dataset's evaluation.

A CI checkout has no `tasks/`, because they're gitignored once a dataset is pushed, so `eval run` pulls the version `lmnr.lock` pins. CI therefore runs the tasks of the commit it checks out: a new version reaches your main branch's CI when the change to `lmnr.lock` is merged. Set `LMNR_PROJECT_API_KEY` and the secrets your `harbor.yaml` and `task.toml` files reference as CI secrets. To skip the downloads on later jobs, cache `~/.cache/lmnr`, or the directory in `LMNR_CACHE_DIR`.

| Exit code | Meaning |
| --- | --- |
| `16` | Invalid evals folder, such as a `harbor.yaml` that sets `datasets` or `tasks`, or an `lmnr.yaml` at the root of `evals/`. Also a packed folder over the upload limit. |
| `17` | `uv` or Docker isn't installed |
| `18` | A dataset's `harbor run` failed. The other datasets still run. |
| `19` | A `${VAR}` placeholder or `LMNR_PROJECT_API_KEY` is unset |
| `20` | A Docker build, pull, or save failed, or an image isn't `linux/amd64` |
| `21` | A `--remote` run failed before its datasets ran, or its sandbox was lost |
| `24` | The version `lmnr.lock` pins isn't in this Laminar project, so the tasks can't be pulled |

`lmnr-cli eval push` and `eval pull` add exit codes `22` and `23`, listed on [Eval datasets](/agent-evaluations/eval-datasets#command-reference).

## Remote limits and image requirements

- **One container per trial.** docker-compose tasks don't run remotely. `cpus` and `memory_mb` above the sandbox limit are clamped, and a run that exceeds the time limit is stopped.
- **The folder upload is capped at 1 GiB.** It includes each dataset's `tasks/` folder. Symlinks, `.git`, `node_modules`, virtualenvs, caches, and `jobs/` directories are skipped, and `.env*` files are never uploaded. Keep large fixtures out of `evals/`.
- **Images need `tar`, `gzip`, and `bash`**, plus `su` if a task runs as a non-root user. They're built for `linux/amd64` (emulated on Apple silicon), so architecture-specific downloads should use `ARG TARGETARCH`.
- **Concurrency is capped per project** (50 sandboxes by default). A higher `--n-concurrent` queues rather than running more at once.
- **Large images** may need a higher `build_timeout_sec` under `[environment]` in `task.toml` (default 600 seconds), which bounds image preparation plus sandbox start.
- **Self-hosted Laminar:** set `LMNR_GRPC_PORT` in your shell or `.env` for `--remote` runs, or the trial traces don't arrive.
