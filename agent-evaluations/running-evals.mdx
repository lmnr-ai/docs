title: Run Agent Evaluations with lmnr-cli eval run
sidebarTitle: Run evals with lmnr-cli
---

`lmnr-cli eval run` runs every [agent evaluation](/agent-evaluations/introduction) dataset in your `evals/` folder, locally on Docker or in Laminar's cloud sandboxes with `--remote`, and records each trial in Laminar with its trace.

Run it from the repo root, since that is where it looks for `.env` and `.env.local`. Use **local** mode while you iterate, after every change. Use **`--remote`** to run many more trials at once. `lmnr-cli` uploads the images and the evals folder, starts the run in Laminar, and prints the run's log until it ends. Results appear in the project as trials finish. Pressing Ctrl-C stops following the log, and the run continues in Laminar.

| | Local | `--remote` |
| --- | --- | --- |
| Harbor runs | On your machine | In a Laminar sandbox |
| Trials run | On your Docker | In Laminar sandboxes, one per trial |
| You need | Docker, uv, `LMNR_PROJECT_API_KEY` | Docker, `lmnr-cli login` (or `LMNR_PROJECT_API_KEY` in CI) |
| Harbor's job output | `evals/<dataset>/jobs/` | `logs/` in the trial's **Files** view in Laminar |

<Note>
Both modes need Docker on the machine where you run `lmnr-cli`, because that is where the images are built. In remote mode the built images are then uploaded.
</Note>

`eval run` runs the tasks in `tasks/` as they are on disk, including edits you haven't pushed. If the dataset's tasks are stored in Laminar, run [`lmnr-cli eval dataset pull`](/datasets/overview#pull-tasks-from-laminar) first on a fresh clone or after `dataset.toml` changes: `eval run` never pulls. It warns when a pinned task is missing or differs from its pin.

```bash
lmnr-cli eval run                                    # every dataset in ./evals
lmnr-cli eval run support --task "duplicate-*" --n-attempts 3
lmnr-cli eval run --task duplicate-charge            # one case
lmnr-cli eval run --remote --n-concurrent 20
lmnr-cli eval run --remote --model anthropic/claude-sonnet-5
lmnr-cli eval run support --group "support (prompt v2)"
```

| Flag | What it does |
| --- | --- |
| `[dataset]` | Run only this dataset, by folder name or `[dataset] name`. Defaults to every dataset. |
| `--dir <dir>` | The evals folder. Defaults to `evals`. |
| `--task <glob>` | Run only tasks whose folder name matches the glob, as Harbor matches them. Repeatable. |
| `--n-attempts <n>` | Trials per task. Overrides `harbor.yaml`. |
| `--n-concurrent <n>` | Concurrent trials. Overrides `harbor.yaml`. |
| `--model <name>` | Agent model. Overrides `harbor.yaml`. |
| `--env KEY[=VALUE]` | Extra agent env var. Repeatable. A bare `KEY` is read from your environment. |
| `--group <name>` | The evaluation group for this run. Defaults to the dataset's name. Needs a single dataset. |
| `--remote` | Run in Laminar sandboxes instead of local Docker. |
| `--json` | Print a JSON summary instead of logs. |

Each run of a dataset is a new evaluation in its [group](/evaluations/comparing-runs#group-runs-to-compare-them): `--group` if you set it, else the `[dataset] name` from `tasks/dataset.toml`, else the folder name. Use `--group` to keep an experiment, such as a new prompt, apart from the main line of runs.

## What you see in Laminar

Each trial is a datapoint in the evaluation, with its verifier's scores and the [trace](/platform/viewing-traces) of the agent run. If the dataset's tasks are stored in Laminar, the evaluation's header links to the dataset, and each trial records the version of the task it ran.

Open a trial and switch to its **Files** view to read the files behind it:

- `task/`: the task the trial ran. For a pushed version it links to the version in the [dataset](/datasets/overview). A `--remote` run that uploaded an unpushed task shows that copy.
- `agent/` (`--remote` only): the dataset's `agent/` folder as it was uploaded with the run.
- `logs/` (`--remote` only): the trial's folder from Harbor, with the agent's `result.json` and logs under `agent/`, the verifier's `reward.json` and output under `verifier/`, and `trial.log`. It arrives when the whole run finishes.

## In CI

Use `--json` and the exit code. A local run prints `{mode: "local", datasets, failed, url}`. A `--remote` run prints `{mode: "remote", uploadId, sandboxId, datasets, url, evaluations, exitCode}` when the run ends. Set `LMNR_PROJECT_API_KEY` and the secrets your `harbor.yaml` references as CI secrets. If your tasks are stored in Laminar, run `lmnr-cli eval dataset pull` before `eval run`.

| Exit code | Meaning |
| --- | --- |
| `16` | Invalid evals folder, or the packed folder is over the upload limit |
| `17` | `uv` or Docker isn't installed |
| `18` | A dataset's `harbor run` failed. The other datasets still run. |
| `19` | A `${VAR}` placeholder or `LMNR_PROJECT_API_KEY` is unset |
| `20` | A Docker build, pull, or save failed, or an image isn't `linux/amd64` |
| `21` | A `--remote` run failed before its datasets ran, or its sandbox was lost |

## Remote limits and image requirements

- **One container per trial.** docker-compose tasks don't run remotely. `cpus` and `memory_mb` above the sandbox limit are clamped, and a run that exceeds the time limit is stopped.
- **The folder upload is capped at 1 GiB.** Symlinks, `.git`, `node_modules`, virtualenvs, caches, and `jobs/` directories are skipped, and `.env*` files are never uploaded. Tasks whose version is already stored in an [dataset](/datasets/overview) aren't uploaded: the run downloads them from Laminar.
- **Images need `tar`, `gzip`, and `bash`**, plus `su` if a task runs as a non-root user. They're built for `linux/amd64` (emulated on Apple silicon), so architecture-specific downloads should use `ARG TARGETARCH`.
- **Concurrency is capped per project** (50 sandboxes by default). A higher `--n-concurrent` queues rather than running more at once.
- **Large images** may need a higher `build_timeout_sec` under `[environment]` in `task.toml` (default 600 seconds), which bounds image preparation plus sandbox start.
- **Self-hosted Laminar:** set `LMNR_GRPC_PORT` in your shell or `.env` for `--remote` runs, or the trial traces don't arrive.
