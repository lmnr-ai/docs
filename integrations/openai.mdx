## Overview

Laminar automatically instruments the official OpenAI package with a single line of code, allowing you to trace and monitor all your OpenAI API calls without modifying your existing code. This provides complete visibility into your AI application's performance, costs, and behavior.

## Getting Started

<Tabs items={['TypeScript', 'Python']}>
  <Tab title="TypeScript">
    ### 1. Install Laminar and OpenAI

    ```bash
    npm install @lmnr-ai/lmnr@latest openai@latest
    ```

    ### 2. Set up your environment variables

    Store your API keys in a `.env` file:

    ```bash
    # .env file
    LMNR_PROJECT_API_KEY=your-laminar-project-api-key
    OPENAI_API_KEY=your-openai-api-key
    ```

    Then load them in your application using a package like [dotenv](https://www.npmjs.com/package/dotenv).

    <Note>
    Using OpenAI inside Next.js? The [Vercel AI SDK page](/integrations/vercel-ai-sdk#next-js-setup) covers the Next.js-specific setup (`serverExternalPackages`, `instrumentation.ts`, and `Laminar.patch` for direct SDK clients).
    </Note>

    ### 3. Initialize Laminar

    Just add a single line at the start of your application or file to instrument OpenAI with Laminar.

    ```typescript
    import { Laminar } from '@lmnr-ai/lmnr';
    import OpenAI from 'openai';
    import 'dotenv/config'; // Load environment variables

    // This single line instruments all OpenAI API calls
    Laminar.initialize({
      instrumentModules: { OpenAI: OpenAI }
    });

    // Initialize OpenAI client
    const openai = new OpenAI.OpenAI();
    ```
    <Note>
    `import OpenAI from 'openai'` imports the module. Pass it to
    `instrumentModules`, then create the client with `new OpenAI.OpenAI()`.
    </Note>

    ### 4. Use OpenAI as usual

    ```typescript
    // Make API calls to OpenAI as you normally would
    const response = await openai.chat.completions.create({
      model: "gpt-5-mini",
      messages: [
        { role: "system", content: "You are a helpful assistant." },
        { role: "user", content: "Hello, how are you?" }
      ],
    });

    console.log(response.choices[0].message.content);
    ```

    All OpenAI API calls are now automatically traced in Laminar.
  </Tab>

## Monitoring OpenAI usage

After instrumenting your OpenAI calls with Laminar, you'll be able to:

1. **View detailed traces** of each OpenAI API call, including request and response
2. **Track token usage and cost** across different models
3. **Monitor latency** and performance metrics
4. **Open LLM span in Playground** for prompt engineering
5. **Debug issues** with failed API calls or unexpected model outputs

Visit your Laminar dashboard to view your OpenAI traces and analytics.

## Enrich your OpenAI traces

- Attach sessions, user IDs, metadata, and tags to OpenAI spans via the [SDK reference](/sdk/reference).
- Wrap the functions around your OpenAI calls with `observe` and mark them as [TOOL spans](/tracing/structure/span-types) so they show up in the transcript.
- Images you send to vision-capable OpenAI models are captured automatically ([Tracing Images](/tracing/structure/images)).

## Decisions API

The [Decisions API](https://developers.openai.com/api/reference/resources/decisions) answers a list of typed questions about a piece of input in one call: predicates (yes or no, with a probability), choices (one value from a fixed list), and scores (a level on a scale). Use it for routing, guardrails, and grading steps in your agent. Laminar traces every `client.decisions.create` call, sync and async, with no extra setup.

<Note>
Decisions tracing is Python-only for now. It needs `lmnr` 0.7.65 or later and `openai` 3.26.0 or later.
</Note>

```bash
pip install -U lmnr 'openai>=3.26.0'
```

```python
from lmnr import Laminar
from openai import OpenAI

Laminar.initialize()

client = OpenAI()

decision = client.decisions.create(
    model="gpt-6-luna",
    input="I was charged twice for my subscription this month. Please fix it today.",
    questions=[
        {
            "type": "choice",
            "name": "queue",
            "instructions": "Which support queue should handle this ticket?",
            "choices": [{"value": "billing"}, {"value": "technical"}, {"value": "account"}],
        },
        {
            "type": "predicate",
            "name": "urgent",
            "instructions": "Does the customer need a response today?",
        },
        {
            "type": "score",
            "name": "frustration",
            "instructions": "How frustrated is the customer?",
            "levels": [{"label": "calm"}, {"label": "annoyed"}, {"label": "angry"}],
        },
    ],
)

for answer in decision.answers:
    print(answer)
```

Each call becomes an LLM span named `openai.decision` that carries:

- The model, and the `input` you sent as the span input. A string becomes a user message, and message lists (including image parts) are recorded as you passed them.
- The full question set, with instructions, choices, and levels for every question, in the span's output schema.
- The typed answers as the span output, with probabilities and confidence intact.
- Token counts, including cached input tokens.
- `safety_identifier`, recorded as the span's user.

Failed calls, such as a question with an empty `choices` list, are marked as errors with the exception recorded. A Decisions call sits in the transcript next to the LLM calls it routes or guards, so you can see the decision next to the action it triggered. `LMNR_TRACE_CONTENT=false` keeps the model and token counts but omits the input, questions, and answers.
